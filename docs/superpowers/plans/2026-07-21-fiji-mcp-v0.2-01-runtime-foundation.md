# Fiji MCP v0.2.0 Runtime Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and prove the strict configuration, private JSON IPC, spawned/contained Fiji worker, serialized coordinator, bounded history, real deadlines, cancellation, and worker recovery that every public tool will use.

**Architecture:** The coordinator remains the sole owner of MCP stdio. It communicates with one spawned worker through `multiprocessing.Connection.send_bytes`/`recv_bytes`, but serializes only strict versioned JSON. The worker redirects native and Java output before importing PyImageJ, initializes Fiji lazily, and is terminated as a process group or Windows Job Object when an executing request cannot safely continue.

**Tech Stack:** Python 3.10–3.12, Pydantic 2.11.x, platformdirs, tomli-w, multiprocessing spawn, asyncio, PyImageJ 1.8.x, pytest, pytest-asyncio, Hypothesis, Ruff, and mypy.

## Global Constraints

- Read the master plan and approved design before starting.
- Use `class X(str, Enum)` instead of `StrEnum` for Python 3.10 compatibility.
- Store owned runtime configuration as TOML, not JSON. Import `tomllib` on Python 3.11–3.12 and the conditional `tomli` backport on Python 3.10; use `tomli-w` to write.
- Configuration can lower a §7.8 limit but cannot raise its hard maximum.
- Do not read legacy `FIJI_MODE`, `FIJI_PATH`, or other environment settings in production runtime code. Tests may set subprocess environment only to locate fixtures.
- Use `multiprocessing.get_context("spawn")` on every platform. Never fork an initialized JVM.
- Do not pickle application messages. `Connection` is transport only; all application payloads are UTF-8 JSON bytes validated by Pydantic.
- Worker output is drained continuously and never forwarded to coordinator stdout/stderr.
- Generation increments when the old worker is invalidated, even if replacement fails.
- Only catalog load/search/describe can retry once after reset. Mutations and generation-bound reads never retry.
- Every regression found here receives a focused test in `tests/regression/`.
- For every task, run its listed focused pytest command immediately after adding the new test and confirm the intended missing-behavior failure; run the same command again after implementation and confirm it passes.

`EffectiveLimits.from_runtime` preserves every runtime field exactly after hard-limit validation and derives public values as follows: `operation_timeout=(min(300, limits.operation_seconds), limits.operation_seconds)`, `page_size=(min(50, limits.default_page_size, limits.maximum_page_size), limits.maximum_page_size)`, `table_page_size=(min(100, limits.default_table_page_size, limits.maximum_table_page_size), limits.maximum_table_page_size)`, and `capture_max_dimension=(min(2_048, limits.capture_dimension), limits.capture_dimension)`. Thus increasing a ceiling never increases the normative default, while lowering a default cap/ceiling lowers omission behavior. `operation_seconds` is an integer because every public timeout is an integer. Config-bound wrappers resolve only through `PUBLIC_NUMERIC_LIMITS`; every runtime field and public binding is covered by a parameterized consumer test.
