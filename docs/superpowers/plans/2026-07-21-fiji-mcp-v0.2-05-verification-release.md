# Fiji MCP v0.2.0 Verification, Cleanup, and GitHub Publication Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Use superpowers:verification-before-completion before claiming any gate passes, superpowers:requesting-code-review before publication, and superpowers:finishing-a-development-branch for the final handoff. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove every retained feature and demo, remove all stale/untested behavior, enforce standard coverage/static/security/artifact gates, and publish the unchanged verified commit as a draft and then ready GitHub pull request.

**Architecture:** `demos/manifest.json` is the closure graph linking claims, tools, CLI commands, clients, profiles, capability/converter families, tests, and evidence. Dedicated verifiers consume pytest collection, coverage JSON, built artifacts, active docs, client evidence, and CI metadata. Publication is same-SHA: any source correction invalidates downstream evidence and restarts the affected gates.

**Tech Stack:** pytest/coverage.py, Ruff, mypy, Bandit, pip-audit, uv, build, twine, JSON Schema, GitHub Actions with pinned runner images/actions, GitHub CLI, real Fiji, and live client evidence.

## Global Constraints

- Finish Plans 01–04 and keep their preliminary Codex-first/client feasibility evidence available outside Git; final release evidence is repeated after this plan freezes the source.
- Every advertised feature must close through the manifest. An unresolved retained-feature bug blocks publication; remove the feature and its claims if it cannot be fixed and tested.
- Aggregate production coverage is at least 90% line and 85% branch. Every production module reaches 80%/75%; safety, IPC/worker, execution routing, and config mutation reach 95%/90%.
- No required test may be skipped. Platform-specific requirements pass in their actual platform jobs.
- Historical `docs/releases/**` stays unchanged in the repository but is excluded from v0.2 package artifacts and active documentation navigation.
- Do not create a v0.2 release-notes document, PyPI workflow, PyPI upload, GitHub release, or tag.
- Preserve user-owned untracked `.agents/`, `.codex/`, `.coverage`, and `AGENTS.md`.
- Push only after the full local preflight passes. Open a draft PR first; make it ready only after same-SHA remote and live-client gates pass.
- Bug reports to the user remain concise: feature, failing behavior, fixed-with-test or removed status.
- For every verifier or gate implementation, run its focused test with the deliberately incomplete/invalid fixture and confirm rejection before implementing the passing behavior; then rerun with both rejecting and passing fixtures.
