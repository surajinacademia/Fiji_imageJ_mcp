# Fiji MCP v0.2.0 Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the pre-v0.2 server with a local, headless, dynamically discovered Fiji gateway that a non-coder can install, diagnose, and use from Codex first and then the remaining verified clients.

**Architecture:** A FastMCP stdio coordinator owns policy, schemas, a bounded queue, audit history, and recovery. A spawned and contained worker owns PyImageJ, the JVM, Fiji catalog, images, tables, and opaque Java objects. A single guided `fiji-mcp` CLI provisions an immutable managed runtime, atomically configures clients, and installs one canonical agent skill.

**Tech Stack:** Python 3.10–3.12, FastMCP 2.14.x, Pydantic 2.11.x, PyImageJ 1.8.x, NumPy, Pillow/tifffile, platformdirs, tomllib/tomli/tomli-w/tomlkit, uv, pytest, Hypothesis, coverage.py, Ruff, mypy, Bandit, pip-audit, build, and twine.

## Global Constraints

- The approved design is authoritative: `docs/superpowers/specs/2026-07-21-fiji-mcp-v0.2-design.md`, SHA-256 `b2dcba9110056ef9fd6318d3ae1505ae6ddfd5157543c95f46a623bfc11ac765` at this plan commit. A design edit must update this checksum and receive review before implementation continues.
- This is a breaking release. Do not retain aliases, environment-variable compatibility, legacy tool schemas, `fiji-mcp-server`, or `fiji-mcp-install`.
- Expose exactly 13 standard tools and exactly 15 trusted tools. Register no workflow, batch, template, extension, or desktop-screenshot tool.
- Headless local stdio is the only transport and mode. Do not add HTTP, web, mobile, GUI, or listening sockets.
- The parent process never imports or initializes PyImageJ/JPype. All Java objects stay in the worker.
- Mutating requests are dispatched at most once. A timeout, cancellation, crash, or unknown outcome never causes a mutation retry.
- `get_fiji_status` is passive and never starts or restarts Fiji.
- Standard mode is a typed interface, not an operating-system sandbox. Documentation and errors must not imply stronger containment.
- Every retained feature needs positive, negative, boundary, serialization, stdio-contract, and real-Fiji evidence where applicable. Fix each discovered defect and add a regression test; remove the feature if it cannot be made reliable.
- Demo outcomes require independent scientific oracles; screenshots and “no exception” are insufficient.
- Codex live acceptance must pass before another client is tested.
- Do not publish to PyPI and do not create v0.2 release notes.
- Preserve the user-owned untracked `.agents/`, `.codex/`, `.coverage`, and `AGENTS.md` paths.
- Before each commit, run the focused tests named by that task, `ruff check` on changed Python files, `ruff format --check` on changed Python files, and `git diff --check`.
- A task is complete only after its expected failure was observed before implementation, its passing command was observed afterward, and the plan checkbox is updated.

## Cross-Plan Contract Freeze

These names and boundaries must remain stable across all five plans. A necessary change requires updating the design spec, every affected plan, generated contract snapshot, docs, and tests in the same commit.

```python
STANDARD_TOOL_NAMES = (
    "get_fiji_status",
    "search_commands",
    "describe_command",
    "run_command",
    "run_plugin",
    "open_image",
    "save_image",
    "close_image",
    "list_images",
    "get_image_info",
    "capture_image",
    "get_results_table",
    "get_operation_history",
)
TRUSTED_ONLY_TOOL_NAMES = ("run_macro", "run_script")
```

All successful tools use `ToolSuccess[T]`. All failures use an MCP `CallToolResult` with `isError=true` and a strict `ToolFailure` in `structuredContent`. `capture_image` additionally returns one native MCP image content block whose declared MIME type matches its bytes.

The only one-retry allowlist is catalog load/search/describe after worker recovery. Image, table, capture, and object reads are generation-bound and are never retried after reset.
