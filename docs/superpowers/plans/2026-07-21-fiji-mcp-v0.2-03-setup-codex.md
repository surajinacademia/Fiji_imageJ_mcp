# Fiji MCP v0.2.0 Guided Setup and Codex-First Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Use superpowers:writing-skills for Task 4. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a non-coder one guided `fiji-mcp` command for setup, diagnosis, status, removal, and serving; install one canonical skill; build all deterministic demo contracts; and pass Codex live acceptance three times before any other client work begins.

**Architecture:** A unified CLI plans changes before writing them, provisions a versioned runtime from an immutable Git revision, commits a journaled multi-file transaction, and verifies the exact generated command over stdio. Client adapters implement detection and config mutation only. The canonical skill and executable demo manifest are versioned package resources, while live evidence stays outside Git under the verified SHA.

**Tech Stack:** Python argparse, platformdirs, tomllib with the Python 3.10 tomli fallback, tomli-w, uv subprocesses, FastMCP stdio client, Pydantic, JSON Schema, NumPy, Pillow/tifffile for deterministic test fixtures, pytest, and Codex CLI/Desktop.

## Global Constraints

- Finish the universal-gateway phase gate before starting.
- The only production entry point after Task 1 is `fiji-mcp`.
- Default setup is interactive and recommends standard profile. Every prompt has a plain-language explanation and a non-interactive flag for tests.
- Setup shows an exact preview before mutation and never silently installs Fiji, Java, uv, AI clients, Fiji plugins, update sites, or models.
- Shared client config is parsed before mutation, written atomically, backed up, and rolled back as a transaction on failure.
- Removal uses the installation manifest and content/value hashes. User-modified files or entries are retained unless forced after explicit confirmation.
- The managed runtime starts offline after initial provisioning and uses an absolute executable plus absolute config path.
- The canonical skill is the only maintained guidance source. Adapter copies are mechanically generated and hash-checked.
- Demos are outcome contracts. Fixtures and expected values are deterministic and independently derived.
- Codex evidence must use clean conversations and clean Fiji sessions, three successes out of three, all on one immutable commit.
- Evidence, auth state, transcripts, and generated client homes are never committed.
- For every implementation task, run its listed focused pytest/demo command after writing the acceptance test and confirm the intended failure; rerun it after implementation and confirm the scientific or contract oracle passes.
